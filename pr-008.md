# Pull Request: feat(hacks-engine): implement SyncHacksUseCase (P2-ETL-008)

## Description

This PR implements the `SyncHacksUseCase`, which serves as the application-layer orchestrator for the full hacks ETL pipeline. It coordinates data flow between the various hexagonal ports (DefiLlama API, HackNormalizer, PostgreSQL Database, DeFiHackLabs GitHub repository, and Redis Cache) to ensure a complete, resilient data ingestion process.

**Task ID:** [P2-ETL-008]

### Key Changes
- **`sync-hacks.use-case.ts`**: Implements the orchestrator logic. Fetches from DefiLlama, normalizes the data, upserts into the database, cross-references Foundry POCs from DeFiHackLabs, and invalidates the Redis cache.
- **`hacks-sync-processor.ts`**: Wires the use case into the BullMQ background processor. Maps the use case `onProgress` callback to BullMQ's `job.updateProgress()`.
- **`worker.ts`**: Bootstrap wiring. Constructs the use case and all its concrete dependencies (adapters) and injects them.
- **Tests**: Adds 16 comprehensive unit tests in `sync-hacks-use-case.test.ts` to cover the execution order, partial failures, error resilience (both fatal and non-fatal), and progress reporting. Also updates `hacks-sync-processor.test.ts` to accommodate the new DI signature.

### Architecture & Design Decisions
- **BullMQ Agnosticism**: The use case is independent of BullMQ. It accepts an `onProgress` callback rather than a `Job` object, preserving clean architecture boundaries.
- **Resilience**: 
  - Failures in DeFiHackLabs cross-referencing or Redis cache invalidation are treated as **non-fatal** (logged as warnings) so the pipeline can still complete the primary data sync.
  - Failures in DefiLlama fetching or Database upserting are **fatal** and re-thrown to trigger a BullMQ retry.
- **Dependency Injection**: Extracted `HackNormalizerPort` to allow for clean mocking and testability without relying on concrete implementations.
